# PostgreSQL и схема ITMessage

Состояние после PR #19. Проект находится на этапе разработки, production-БД пока нет. Поэтому вместо поддержки эволюции старых схем у Alembic **одна начальная миграция**:

```text
backend/migration/
├── env.py
├── script.py.mako
└── versions/
    └── 001_initial_schema.py
```

Она создаёт пять таблиц: `users`, `chats`, `files`, `messages` и `file_cleanup_tasks`. В неё входят ограничения, внешние ключи, индексы, включая GIN и уникальный B-tree для массива участников чата.

## Важно: только новая пустая БД

Эта ревизия **не является апгрейдом существующей локальной БД**, созданной старой цепочкой Alembic. Старые revision ID больше не существуют в репозитории. Если в старой БД есть нужные данные, сначала сделайте резервную копию, например `pg_dump`. Команда `docker compose down -v` удаляет том PostgreSQL и **безвозвратно стирает содержимое** этого тома; используйте её только для одноразовой dev-БД.

Рекомендуемый способ перехода в разработке: создать **новую пустую** базу или новый Docker volume, затем:

```bash
cd backend
alembic heads
alembic upgrade head
alembic current
alembic check
```

`alembic check` сравнивает фактическую схему БД с `Base.metadata` и не должен находить новых операций. Полная проверка кругового перехода `upgrade → downgrade base → upgrade` выполняется **только в одноразовой БД CI**.

## Поведение на старых данных

- Миграция не содержит `TRUNCATE`, `DROP ... CASCADE` для произвольных старых таблиц или других автоматических операций, уничтожающих существующие данные.
- При указании существующего revision ID Alembic не сможет продолжить по новой цепочке; не пытайтесь исправить это через `alembic stamp` без проверки фактической структуры.
- Удаление старой локальной БД — осознанное действие разработчика после резервного копирования, **не автоматическая часть приложения**.

## Проверки

GitHub Actions запускает на чистой PostgreSQL:

1. `alembic heads` — одна вершина.
2. `alembic upgrade head` и `alembic current`.
3. `alembic check` — сравнение с SQLAlchemy.
4. `alembic downgrade base`, новый `alembic upgrade head`, повторный `alembic check`.
5. HTTP smoke с реальными пользователями, чатами и сообщениями; Docker Compose smoke с **четырьмя Uvicorn-воркерами**, RSA и проверкой перезапуска.

Текущая схема сущностей показана в [architecture.md](architecture.md).
